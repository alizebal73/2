## ۰) اصل غیرقابل‌مذاکره توسعه و تکمیل محصول

این پروژه با هدف رسیدن به یک سیستم قابل استفاده واقعی در گیم‌نت ساخته می‌شود؛ بنابراین معیار اصلی، **درستی معماری و رفتار واقعی سیستم در عمل** است، نه صرفاً سبز شدن CI یا عبور موقت از یک خطا.

- هر مشکل ابتدا در سطح علت ریشه‌ای، مدل داده، مرز مسئولیت‌ها، همزمانی، persistence، قراردادها و وابستگی‌ها بررسی می‌شود؛ سپس کد تغییر می‌کند.
- وصله‌ای که فقط تست فعلی را سبز کند ولی بدهی معماری، رفتار جعلی، race condition، ناسازگاری migration یا مشکل release/update ایجاد کند پذیرفته نیست.
- تست‌ها باید رفتار واقعی محصول را اثبات کنند و برای سبز شدن ضعیف یا حذف نمی‌شوند.
- تغییر هر Stage باید اثرش بر Stageهای قبلی، migration، update/rollback، deployment، امنیت، performance و مسیرهای واقعی مشتری بررسی شود.
- Server همچنان تنها منبع حقیقت است و تمام stateهای حساس باید persistence و مسیر recovery معتبر داشته باشند.
- «Done» فقط وقتی ثبت می‌شود که implementation واقعی، تست مناسب، CI مربوط به همان SHA و شواهد عملی موردنیاز آن Stage وجود داشته باشد.
- هدف نهایی، محصولی پایدار و قابل اتکا برای استفاده روزمره در گیم‌نت است؛ سرعت توسعه در برابر correctness اولویت پایین‌تری دارد.


## ۱) نمای کلی سیستم (۳ جزء اصلی)

```
┌──────────────────────────────────────────────────────────────┐
│                        سرور (Server)                          │
│  • دیتابیس مرکزی (تنها منبع حقیقت)                            │
│  • API داخلی (REST/WebSocket)                                 │
│  • منطق تجاری: تایمر، تعرفه، فاکتور، کیف پول، گزارش            │
│  • سرویس تایمر مرکزی (قطع برق/کرش → recovery خودکار)          │
└──────┬───────────────────────┬───────────────────────────────┘
       │ HTTPS/WSS در شبکه داخلی │
┌──────▼──────────────┐  ┌─────▼─────────────────────────────┐
│   داشبورد (Web)     │  │   کلاینت (فقط روی ۴۰ کیس)          │
│  اپراتور/مدیر       │  │  • قفل ویندوز + پوسته بازی         │
│  گرید ۶۱ ایستگاه    │  │  • نمایش زمان باقیمانده            │
│  بوفه، مشتری، گزارش │  │  • فرمان‌ها: قفل/باز/ری‌استارت      │
│  چند صندوقه هم‌زمان │  │  • Heartbeat هر چند ثانیه          │
└─────────────────────┘  └───────────────────────────────────┘

PS5 / PS4 / فوتبال‌دستی → ❌ بدون کلاینت — فقط تایمر در داشبورد + آلارم
```

**منطق کلیدی:** سرور مرکزی یعنی «یک منبع حقیقت». اگر اپراتور وسط بازی برنامه را ببندد یا برق برود، با ری‌استارت، جلسات باز از روی دیتابیس **بازیابی** می‌شوند و زمانِ قطعی هم محاسبه و لحاظ می‌شود (گیم تایمر همین را می‌فروشد: «حفظ کلیه اطلاعات در قطع ناگهانی برق»).

## ۲) اجزا به تفصیل

### ۲.۱) سرور
- **وظایف:** ذخیره‌سازی، محاسبه هزینه لحظه‌ای، مدیریت جلسات، فرمان‌دهی کلاینت‌ها، آمار و گزارش
- **دیتابیس:** SQLite (تک صندوقه، ساده‌ترین بکاپ: یک فایل) یا PostgreSQL (چند صندوقه/چند اپراتور سنگین)
- **API:** REST برای CRUD + WebSocket برای تایمر زنده و فرمان‌ها
- **Biller Engine:** محاسبه هزینه بر اساس (تعرفه × زمان) + آیتم‌های بوفه + تخفیف
- **Recovery:** جلسه باز = Active در دیتابیس؛ روشن شدن سرور → جلسات باز ادامه می‌یابند
- **بکاپ:** خودکار روزانه فایل دیتابیس + نگهداری ۳۰ نسخه

### ۲.۲) داشبورد (برنامه صندوقه / اپراتور)
- **تکنولوژی پیشنهادی:** Web App (React) که از سرور لوکال سرو می‌شود
  - چرا وب؟ چند صندوقه هم‌زمان، باز شدن روی تبلت برای مدیر، آپدیت آسان، فارسی/RTL راحت‌تر
- **پوسته‌ی دسکتاپ مستقل (درخواست کاربر):** داشبورد در **پنجره‌ی تکی اختصاصی برنامه** باز می‌شود، نه تب مرورگر کروم:
  - **راه حل منتخب: WebView2** (موتور Edge روی ویندوز، از قبل نصب — بازی‌نت هم همین است) → یک برنامه‌ی ویندوزی کوچک که صفحه‌ی React سرور را داخل خودش لود می‌کند؛ آیکون مستقل، مینیمایز به تسک‌بار، F1-F9 برنامه را می‌گیرد و به مرورگر اینترنت کاربر ربطی ندارد
  - جایگزین: Tauri (سبک‌تر ولی نیازمند Rust)
  - HMR توسعه هم داخل همین پوسته کار می‌کند
- **صفحه‌ها:**
  1. **داشبورد زنده** — گرید ۶۱ ایستگاه با رنگ وضعیت، تایمر زنده، دکمه شروع/پایان/تمدید/انتقال
     - زون‌بندی گرید بر اساس نوع: رایانه‌ها / کنسول‌ها / میزها (الگوی LaunchDesk) + خط انتظار (زیرووان)
  2. **جلسه فعال** — جزئیات یک جلسه: نفرات، تعرفه، افزودن بوفه، تخفیف، تسویه
  3. **بوفه/POS** — فروش سریع با جست‌وجو، کیبورد شماره‌ای، وصل به جلسه یا مستقل
  4. **مشتریان** — پروفایل، کیف پول، بدهی، تاریخچه
  5. **گزارش‌ها** — روزانه/ماهانه/سالانه نموداری، تفکیک نقد/کارت، کارکرد ایستگاه‌ها، شیفت
  6. **تعرفه‌ها** — جدول تعرفه با بازه ساعتی و نفرات
  7. **تنظیمات** — ایستگاه‌ها، صداها، تم، کاربران و دسترسی‌ها، بکاپ
- **UX کلیدی:** همه عملیات پرمصرف (شروع/تمدید/بستن/بوفه) از خود کارت ایستگاه انجام شود — اپراتور نباید بین صفحه‌ها پرش کند

### ۲.۳) کلاینت PC (فقط ۴۰ کیس؛ PS5/PS4/فوتبال‌دستی ندارند)
- **شکل:** برنامه ویندوزی کوچک که **جایگزین شل (Shell) ویندوز** یا روی آن قفل می‌شود
- **وظایف:**
  - لاگین مشتری با کد/کارت عضویت (یا باز شدن توسط اپراتور)
  - نمایش **زمان باقیمانده زنده**، مانده حساب، نام مشتری
  - **قفل** دسترسی به ویندوز، تسک‌منیجر، درایوها
  - اجرای بازی فقط از پوسته + جلوگیری از اجرای هم‌زمان چند بازی
  - هشدار صوتی/تصویری پایان وقت (قابل تنظیم از سرور)
  - Heartbeat هر ۵–۱۰ ثانیه؛ قطع ارتباط → مطابق سیاست: ادامه/قفل
  - فرمان‌ها: قفل، باز کردن، ری‌استارت، خاموش، Logoff، پیام
- **تکنولوژی پیشنهادی:** C#/.NET (WPF/WinForms) — سبک، سرویس‌پذیر، دسترسی سیستمی برای قفل شل
- **امنیت مهم:** کلاینت هیچ تصمیم مالی نمی‌گیرد؛ فقط نمایش + اجرای فرمان. امنیت را سرور تضمین می‌کند (کلاینت قابل هک است!)

## ۳) فلوچارت اصلی عملیات (سفارش استاندارد)

```
مشتری می‌آید
   │
   ▼
[ایستگاه آزاد؟] ── نه ──► لیست انتظار / رزرو
   │ بله
   ▼
شروع جلسه در داشبورد (انتخاب تعرفه + نفرات + پیش‌پرداخت یا پس‌پرداخت)
   │
   ▼
تایمر زنده شروع می‌شود ──► (کنسول/میز: فقط آلارم داشبورد)
   │                      (PC: کلاینت نمایش می‌دهد + سرور فرمان می‌دهد)
   ▼
(حین بازی) سفارش بوفه به فاکتور اضافه می‌شود / تغییر تعرفه / جابه‌جایی ایستگاه / تمدید
   │
   ▼
پایان: هشدار پایان + تسویه (نقد/کارت/کیف پول) + چاپ فاکتور (اختیاری)
   │
   ▼
ایستگاه آزاد → گزارش‌ها آپدیت می‌شوند
```

## ۴) فازبندی اجرا

| فاز | محتوا | خروجی قابل استفاده |
|---|---|---|
| **فاز ۱ (MVP)** | سرور + دیتابیس + داشبورد: ایستگاه‌ها، تعرفه، تایمر، فاکتور، نقد/کارت، گزارش روزانه، بکاپ، کاربر مدیر/اپراتور | گیم‌نت بدون کلاینت قابل مدیریت است (مثل نسخه Pro داخلی‌ها) |
| **فاز ۲** | بوفه/انبار + کیف پول و بدهی مشتری + گزارش نموداری ماهانه/سالانه + بستن شیفت | مدیریت مالی کامل |
| **فاز ۳** | **کلاینت ویندوزی برای ۴۰ کیس**: قفل، پوسته، تایمر روی مانیتور مشتری، فرمان‌ها، Heartbeat | کنترل خودکار PCها |
| **فاز ۴** | رزرو آنلاین + تورنمنت + پیامک + چاپ حرارتی + اپ موبایل مدیر | ویژگی‌های تمایز |

**دلیل این ترتیب:** نسخه Pro بازار ایران (بدون کلاینت) دقیقاً معادل فاز ۱+۲ ماست و خودش محصول کامل قابل فروش است. کلاینت (فاز ۳) پیچیده‌ترین بخش فنی و مخصوص PCهاست — پس آخر می‌آید.

## ۶) ریسک‌ها و نکات مهم

1. **امنیت کلاینت:** کلاینت روی سیستم مشتری است و قابل دور زدن است → سیاست «سرور مرجع»: اگر کلاینت قطع شد، سرور همچنان حساب می‌کند
2. **قطع برق:** جلسات باید از دیتابیس بازیابی شوند، نه از حافظه؛ زمان قطعی هم باید در محاسبه بیاید
3. **شمسی بودن تاریخ:** از روز اول در دیتابیس لحاظ شود (بعداً اضافه کردنش دردسرساز است)
4. **همگام‌سازی چند اپراتور:** اگر دو صندوقه باشد، WebSocket و قفل‌گذاری روی جلسه از روز اول لازم است
5. **مقیاس:** گرید ۶۱ ایستگاهی باید روی یک صفحه بدون اسکرول زیاد جا شود (کارت‌های جمع‌وجور + زون‌بندی)
